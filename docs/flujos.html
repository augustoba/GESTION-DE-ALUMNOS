1. Descripción General del Sistema

Qué es, para qué sirve y cómo se organiza

El Sistema de Gestión de Alumnos del IES Alfredo Coviello es una aplicación web que digitaliza y centraliza todos los procesos académicos de la institución: desde la primera preinscripción de un aspirante hasta el seguimiento diario de asistencia durante el año cursado.

¿Qué problema resuelve? El proceso de ingreso era 100% en papel. El sistema permite registrar formularios, realizar el seguimiento presencial, gestionar pagos en efectivo, verificar documentación física, asignar turnos de atención y habilitar alumnos, todo desde una interfaz unificada.

Roles del sistema

El sistema tiene 4 roles, cada uno con acceso y responsabilidades diferentes:

RolQuién esQué puede hacerCómo accede
SUPER_ADMIN Director / TI Crea admins y docentes, configura carreras, períodos, calendario, permisos Cuenta creada en el DataInitializer
ADMIN Personal administrativo Gestiona preinscripciones, pagos, documentación, turnos, alumnos Creado por SUPER_ADMIN vía sistema
DOCENTE Profesor Ve sus materias, lista de alumnos, corrige asistencias, gestiona reinscripciones Creado por SUPER_ADMIN vía sistema
ALUMNO Estudiante habilitado Ve su perfil, materias, asistencia, documentos digitales Se crea automáticamente al habilitar preinscripción

🔐 Autenticación

Todos los usuarios (excepto aspirantes) acceden con email + contraseña. El sistema devuelve un JWT que debe enviarse en cada petición posterior como Authorization: Bearer <token>.

🌐 URLs del sistema

Backend API: http://localhost:8080
Frontend: http://localhost:4200
El frontend ya tiene configurado el proxy para redirigir las llamadas al backend.

2. SUPER_ADMIN — Camino Feliz

El administrador raíz. Configura la institución y gestiona el acceso del personal.

Credenciales iniciales Email: superadmin@coviello.com  |  Contraseña: Admin1234
Estas credenciales se crean automáticamente al iniciar el backend por primera vez.

2.1 — Crear un ADMIN o DOCENTE

El SUPER_ADMIN es el único que puede crear cuentas para el personal del instituto. El nuevo usuario recibe un email con sus credenciales temporales.

  1. 1
    Login del SUPER_ADMIN Ingresar a http://localhost:4200 con el email y contraseña del super admin. El sistema redirige automáticamente a /admin/lista.
  2. 2
    Ir a Usuarios desde el menú lateral En la barra lateral izquierda aparece el ítem "Usuarios" (solo visible para SUPER_ADMIN).
  3. 3
    Completar el formulario de creación Ingresar email (será el nombre de usuario), contraseña temporal y seleccionar el rol (ADMIN o DOCENTE).
  4. 4
    El sistema envía un email de bienvenida El nuevo usuario recibe sus credenciales por email y puede ingresar al sistema.
POST/api/admin/usuarios // Solo SUPER_ADMIN { "username": "lgomez@coviello.edu.ar", "password": "PasswordTemporal123", "rol": "ADMIN" // o "DOCENTE" } GET /api/admin/usuarios // Listar admins y docentes DEL /api/admin/usuarios/{id} // Desactivar (no puede desactivar SUPER_ADMIN)

2.2 — Otorgar permisos granulares a un ADMIN

El SUPER_ADMIN puede otorgar permisos específicos a cada ADMIN, con fecha de vencimiento opcional.

POST/api/permisos { "usuarioId": 5, "codigoPermiso": "GESTIONAR_CARRERAS", "fechaHasta": "2026-12-31T23:59:59" // null = sin vencimiento } GET /api/permisos/usuario/{usuarioId} // Ver permisos activos de un admin DEL /api/permisos/{permisoId} // Revocar permiso

2.3 — Configurar carreras, años y comisiones

La jerarquía es: Carrera → Año (AnioCarrera) → Comisión. Los cupos y prefijos de turno se configuran por comisión, no por carrera.

Crear una carrera

POST/api/carreras { "nombre": "Tecnicatura en Informática", "descripcion": "Carrera de 3 años", "activa": true } GET /api/carreras // Lista de carreras GET /api/carreras/{id} // Detalle con años y comisiones PUT /api/carreras/{id} DEL /api/carreras/{id}

Crear comisiones por año

// 1° agregar un año a la carrera: POST/api/carreras/{id}/anios { "numeroAnio": 1 } // 2° crear comisión dentro del año: POST/api/carreras/anios/{anioId}/comisiones { "nombre": "Comisión A", "cupoMaximo": 30, // 0 = sin límite "prefijoTurno": "A", // genera A1, A2... "activa": true } PUT /api/carreras/comisiones/{id} DEL /api/carreras/comisiones/{id}
Ejemplo: 1° año de Informática con dos secciones Se crean dos comisiones: "Comisión A" (mañana, cupo 30) y "Comisión B" (tarde, cupo 25). Al habilitar un aspirante, el ADMIN elige en cuál de las dos queda inscripto.

Crear un período de inscripción

POST/api/periodos-inscripcion { "nombre": "Preinscripción 2026", "fechaInicio": "2026-11-01", "fechaFin": "2026-12-15", "tipo": "PREINSCRIPCION" }

Tipos: PREINSCRIPCION, REINSCRIPCION. Solo uno activo por tipo.

2.4 — Calendario académico y emails masivos

POST/api/calendario // Agregar feriado o evento { "fecha": "2026-07-09", "tipo": "FERIADO_NACIONAL", "descripcion": "Independencia" } POST/api/mails/enviar // Email masivo { "asunto": "Inicio de clases", "cuerpo": "...", "destinatarioTipo": "TODOS" } // destinatarioTipo: TODOS | POR_CARRERA | POR_ANIO | DOCS_FALTANTES

3. ADMIN — Camino Feliz

El personal administrativo. Gestiona el proceso diario de preinscripciones y alumnos.

Credenciales iniciales Email: admin@coviello.com  |  Contraseña: Admin1234

3.1 — Ver y buscar preinscripciones

Cuando un aspirante llega a la institución, el ADMIN lo ubica en el sistema por código, DNI o nombre.

GET /api/preinscripciones?page=0&size=20 GET /api/preinscripciones/estado/PENDIENTE?page=0&size=20 GET /api/preinscripciones/buscar/codigo?codigo=PRE-2026-00042 GET /api/preinscripciones/buscar/dni?dni=30123456 GET /api/preinscripciones/buscar/nombre?nombre=Juan&apellido=Pérez&page=0 GET /api/preinscripciones/{id} // Detalle completo con pago y checklist

3.2 — Registrar pago en efectivo

Los pagos son acumulativos. Se puede registrar en cuotas; el sistema calcula el estado automáticamente.

Diagrama 2 — Estados del pago (acumulativo en efectivo)

POST/api/preinscripciones/{id}/pago { "monto": 2500.00, // monto a acumular esta vez "montoTotal": 5000.00 // monto total de matrícula (opcional) } // Respuesta incluye: estado (SIN_PAGO|PARCIAL|COMPLETO), montoAbonado, montoTotal

3.3 — Checklist de documentación física

El aspirante trae documentos físicos. El ADMIN marca en el sistema cuáles presentó. No se suben archivos — es solo un registro de presencia física.

3.4 — Proceso de revisión y habilitación

El ADMIN sigue un flujo de 3 estados para aprobar o rechazar una preinscripción:

Diagrama 3 — Máquina de estados de la preinscripción

PUT /api/preinscripciones/{id}/en-revision // PENDIENTE → EN_REVISION PUT /api/preinscripciones/{id}/rechazar // → RECHAZADO // Habilitar requiere seleccionar comisión: PUT /api/preinscripciones/{id}/habilitar // → HABILITADO (crea Alumno + Usuario) { "comisionId": 3 // ID de la comisión elegida por el ADMIN } // Error 400 si la comisión no tiene cupo disponible
¿Qué ocurre al habilitar? El ADMIN primero selecciona la comisión (sección) del año correspondiente donde quedará inscripto el aspirante. El sistema verifica el cupo disponible y luego crea automáticamente: (1) un registro Alumno asignado a la comisión elegida, (2) un Usuario con rol ALUMNO (contraseña bloqueada hasta activación), y (3) envía al aspirante un email con un enlace de activación (válido 72 hs) que lo lleva a /auth/activar?token=UUID para elegir su propia contraseña.

3.5 — Asignar turno de atención presencial

POST/api/turnos/configuracion // Primero configurar el turno (SUPER_ADMIN) { "nombre": "Turnos Diciembre 2026", "fecha": "2026-12-10", "horarioInicio": "08:00", "horarioFin": "13:00", "intervaloMinutos": 15 } POST/api/turnos/asignar/{preinscripcionId} // ADMIN asigna el turno // Sistema genera: numeroTurno = "A42", horaAsignada = "08:45", token UUID // El alumno recibe email con turno y link de confirmación

4. DOCENTE — Camino Feliz

El profesor gestiona sus materias, alumnos y asistencias desde su portal.

¿Cómo obtiene su cuenta? El SUPER_ADMIN crea la cuenta del docente desde /admin/usuarios. El docente recibe sus credenciales por email y puede hacer login inmediatamente.

4.1 — Ver mis materias y alumnos

  1. 1
    Login en el sistema El sistema redirige automáticamente a /docente/portal.
  2. 2
    Ver mis materias asignadas El portal muestra las materias donde el docente tiene horarios de clase asignados.
  3. 3
    Ver alumnos de una materia Al seleccionar una materia, ver la lista de alumnos con inscripción confirmada.
GET /api/docente-portal/mis-materias // Devuelve: lista de materias con nombre, carrera, año GET /api/docente-portal/mis-alumnos/{materiaId} // Devuelve: alumnos habilitados con inscripción CONFIRMADA GET /api/docente-portal/alumno/{alumnoId} // Detalle completo del alumno (datos personales, asistencia, etc.)

4.2 — Gestión de asistencia

El docente puede ver la asistencia registrada automáticamente por el Arduino, corregir errores manualmente y consultar resúmenes de regularidad.

GET /api/asistencias/horario/{horarioClaseId}?fecha=2026-04-15 // Lista de registros de asistencia para esa clase en esa fecha GET /api/asistencias/resumen/{alumnoId}/{materiaId}?desde=2026-03-01&hasta=2026-06-30 // Devuelve: total clases, presentes, tardanzas, ausentes, % asistencia, riesgo libre GET /api/asistencias/calendario/{materiaId}?desde=2026-03-01&hasta=2026-06-30 // Mapa fecha → [asistencias] para vista calendario PUT /api/asistencias/{asistenciaId} { "estado": "AUSENTE", // PRESENTE | AUSENTE "justificacion": "No se presentó ese día" }

4.3 — Gestionar solicitudes de reinscripción

GET /api/inscripciones-materia/materia/{materiaId}?estado=PENDIENTE // Ver solicitudes pendientes en esta materia PUT /api/inscripciones-materia/{inscripcionId}/resolver { "estado": "CONFIRMADA" } // o "RECHAZADA"

5. ALUMNO — Camino Feliz

El estudiante. Puede registrarse directamente en el sistema o iniciar el proceso con una preinscripción pública.

Dos puntos de entrada:
(A) Registro directo → el aspirante completa el formulario en /registro y recibe un email de bienvenida.
(B) Preinscripción pública → llena el formulario en /preinscripcion, concurre al instituto y el ADMIN lo habilita. En ambos casos, las credenciales de acceso llegan por email.

5.1 — Registro en el sistema

El aspirante puede crear su propia cuenta desde la pantalla de Registro, sin necesidad de que el ADMIN lo cree previamente.

  1. 1
    Acceder a la pantalla de Registro Desde el login, hacer clic en "¿No tenés cuenta? Registrate". La URL es http://localhost:4200/registro (ruta pública, no requiere login).
  2. 2
    Completar el formulario Nombre, apellido, DNI, email, contraseña y confirmación de contraseña. La contraseña debe tener al menos 8 caracteres.
  3. 3
    El sistema crea la cuenta Se crea el usuario con rol ALUMNO y se envía un email de bienvenida con las credenciales confirmadas.
  4. 4
    Redirigir al login Tras 3 segundos de mostrar el mensaje de éxito, la pantalla redirige automáticamente a /login.
POST/api/auth/registro // Sin autenticación (ruta pública) { "nombres": "Juan", "apellidos": "Pérez", "dni": "30123456", "email": "juan.perez@gmail.com", "password": "MiPassword123" } // Respuesta: 201 Created + email de bienvenida enviado al email indicado

5.2 — Preinscripción (sin cuenta — acceso público)

El formulario de preinscripción es público. El aspirante accede a http://localhost:4200/preinscripcion sin necesidad de registrarse ni iniciar sesión.

  1. 1
    Completar el formulario web Nombre, apellido, DNI, email, datos personales y carrera de interés.
  2. 2
    Enviar el formulario Al enviar, el sistema genera un código único PRE-2026-00042 y lo muestra en pantalla.
  3. 3
    Recibir el PDF por email El sistema envía automáticamente un PDF con el formulario completo y el código. El aspirante debe imprimirlo y llevarlo el día de la inscripción presencial.
  4. 4
    Presentarse con la documentación El aspirante concurre con el formulario impreso y los documentos requeridos. El ADMIN lo atiende y gestiona todo en el sistema.
POST/api/preinscripciones // Sin autenticación (ruta pública) { "nombre": "Juan", "apellido": "Pérez", "dni": "30123456", "email": "juan.perez@gmail.com", "fechaNacimiento": "2000-05-14", "direccion": "Av. Colón 1234", "telefono": "3512345678", "carreraId": 1 } // Respuesta: 201 Created + codigoFormulario: "PRE-2026-00042" + PDF enviado al email

5.3 — Confirmar turno por email

Cuando el ADMIN asigna un turno, el aspirante recibe un email con un link de confirmación. No requiere login.

GET /api/turnos/confirmar?token=3f8a2c1d-... // Sin autenticación // El sistema marca el turno como confirmado // Respuesta: 200 OK con el número de turno y hora asignada

5.4 — Activar cuenta (primer acceso vía preinscripción)

Cuando el ADMIN hace clic en "Habilitar alumno", el sistema no asigna una contraseña temporal: en su lugar genera un token UUID de activación (válido 72 horas) y envía un email al aspirante.

Este flujo aplica solo al Path B (preinscripción → habilitación por ADMIN).
El Path A (/registro) no pasa por aquí: el alumno ya eligió su contraseña al registrarse.
  1. 1
    El aspirante recibe el email de activación El asunto dice "Activá tu cuenta — IES Alfredo Coviello". Contiene un link de la forma http://localhost:4200/auth/activar?token=<UUID>.
  2. 2
    El sistema valida el token Al entrar al link, el frontend llama a GET /api/auth/validar-token?token=.... Si el token es inválido o expiró, muestra un mensaje de error con instrucciones.
  3. 3
    El alumno elige su contraseña La pantalla muestra dos campos: Nueva contraseña (mínimo 8 caracteres) y Confirmar contraseña. Ambos deben coincidir. Incluye botón de "ver/ocultar" para cada campo.
  4. 4
    El sistema activa la cuenta POST /api/auth/activar guarda la contraseña en la DB (hash bcrypt) y elimina el token. Muestra mensaje de éxito y redirige al login automáticamente a los 4 segundos.
GET /api/auth/validar-token?token=3f8a2c1d-... // Sin autenticación // 200 OK → { email: "juan@...", nombres: "Juan" } // 400 BAD REQUEST → token inválido o expirado POST /api/auth/activar // Sin autenticación { "token": "3f8a2c1d-...", "password": "MiNuevaContrasena123" } // 200 OK → cuenta activada, token eliminado de la DB // 400 BAD REQUEST → token inválido/expirado o password < 8 caracteres

5.5 — Recuperar contraseña

Si el alumno (o cualquier usuario) olvidó su contraseña, puede solicitar el restablecimiento desde la pantalla de login.

  1. 1
    Hacer clic en "¿Olvidaste tu contraseña?" En la pantalla de login, debajo del botón de ingreso, aparece el enlace para recuperar acceso.
  2. 2
    Ingresar el email registrado Se muestra un formulario donde el usuario escribe el email con el que se registró.
  3. 3
    El sistema envía una nueva contraseña Si el email existe en el sistema, se genera una contraseña temporal y se envía al correo indicado.
  4. 4
    Ingresar con la contraseña recibida El usuario inicia sesión con la contraseña temporal y puede cambiarla desde su perfil.
POST/api/auth/recuperar-password // Sin autenticación (ruta pública) { "email": "juan.perez@gmail.com" } // Si el email existe → genera contraseña temporal y la envía por correo // Respuesta: 200 OK (siempre, para no revelar si el email existe)

5.6 — Portal del alumno (una vez activada la cuenta)

Con la cuenta activada, el alumno ingresa con su email y la contraseña que eligió en el paso anterior.

POST /api/auth/login { "username": "juan.perez@gmail.com", "password": "MiNuevaContrasena123" } GET /api/perfil // Ver mis datos GET /api/perfil/documentos // Ver mis documentos digitales GET /api/inscripciones-materia/mis-inscripciones // Mis materias GET /api/asistencias/resumen/{miId}/{materiaId} // Mi asistencia

📄 Reinscripción a materias

Durante el período REINSCRIPCION, el alumno solicita las materias que cursará:

POST/api/inscripciones-materia { "materiaIds": [3, 7, 12] }

Estado inicial: PENDIENTE hasta que el ADMIN/DOCENTE confirme.

📁 Documentos digitales

Durante el año, puede subir documentos para su legajo (URL de archivo ya alojado):

POST/api/documentos-digitales/alumno/{id} ?tipoDocumento=TITULO_SECUNDARIO &archivoUrl=https://...

El ADMIN lo revisa: PENDIENTE → VALIDADO / RECHAZADO.
